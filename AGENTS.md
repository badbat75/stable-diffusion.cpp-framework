# Project guide

## Project overview

Windows-only PowerShell scripts to install prerequisites, configure, build, and run [stable-diffusion.cpp](https://github.com/leejet/stable-diffusion.cpp) on Windows with GPU backend support (CUDA, Vulkan, ROCm/HIP) and NSIS installer packaging. Primary workflow uses `sd-cli` for one-off image generation; `sd-server` provides an optional API endpoint. No separate web UI is bundled — users interact via the CLI or a browser at the server port.

## Structure

- `build\config-build.psd1` — build-time configuration (paths, GPU targets, compiler flags). Generated by `01-configure.ps1`; lives under `build\` (whole dir gitignored). Runtime / per-model settings are **not** stored at repo root — they live under `%LOCALAPPDATA%\stable-diffusion.cpp\config\` and are written by `resources\config-generate.ps1` / `config-model.ps1` on first launch or by the NSIS install-time page.
- `common.ps1` — shared bootstrap: loads `$cfg` from `build\config-build.psd1`, adds ROCm/HIP\bin to (if detected and enabled), exposes `Enable-VsDevShell`. Only build/package scripts call it.
- `00-install-prerequisites.ps1` — idempotent toolchain bootstrapper: installs and updates winget-tracked packages (PowerShell 7+ / NSIS) in a single UAC-elevated session, clones `leejet/stable-diffusion.cpp --recursive`, then probes for CUDA Toolkit / Vulkan SDK / AMD HIP SDK. Reads `build\config-build.psd1` directly so it works on a fresh machine before `01-configure.ps1` has run.
- `01-configure.ps1` — auto-detects VS DevShell, cmake, ninja, git, and GPU toolchains, writes `build\config-build.psd1` with paths and GPU toggle flags (`SdCuda`, `SdVulkan`, `SdHipblas`).
- `02-build.ps1` — dot-sources `common.ps1`; calls `Enable-VsDevShell`. CMake configure into `build\cmake-build` using `-DSDBUILD_EXAMPLES=ON` and GPU toggles; builds with Ninja/MSVC. Auto-clones/syncs sd.cpp source recursively (`--recursive` for ggml submodule).
- `03-package.ps1` — dot-sources `common.ps1`; stages sd-cli.exe, sd-server.exe + runtime scripts into `build\staging\`, renders NSIS template, builds installer to `.\dist\`.
- `resources\run-generate.ps1` — main "Generate Image" Start Menu shortcut. Scans the configured ModelsFolder for `.gguf` / `.safetensors` files, shows model picker, gathers prompt/negative prompt/dimensions/steps/CFG/sampling method/seed, invokes sd-cli, saves timestamped PNG to OutputDir. Also accepts `-Auto` flag (uses DefaultModelName, skips model picker).
- `resources\config-generate.ps1` — generation defaults config writer (`%LOCALAPPDATA%\stable-diffusion.cpp\config\config.ini`). Interactive wizard for ModelsFolder, SD Server port, output directory, server enable/disable. Also supports `-NonInteractive` mode (used by NSIS install-time page) and `-DumpIni <path>` (emits current INI to `$PLUGINSDIR` for NSIS `.onInit`).
- `resources\config-model.ps1` — per-model preset builder. Operates on `%LOCALAPPDATA%\stable-diffusion.cpp\config\models.ini`. Prompts for model file path, prompt, negative prompt, width, height, steps, CFG scale, sampling method, seed. Rewrites only the matching section while preserving all others byte-for-byte (including comments).
- `resources\common-ini.ps1` — shared INI helpers dot-sourced by all three runtime scripts and config-generate.ps1. Exposes `Read-ConfigIni`, `Set-ConfigField`, `Read-ModelEntry`, `Write-ModelSection`.
- `stable-diffusion-cpp.nsi.template` — NSIS installer with custom nsDialogs page (models folder browser, SD server port, output dir, thread defaults). Post-install runs `config-generate.ps1 -NonInteractive` to write `config.ini`. Start Menu shortcuts: "Generate Image", "Configure Model", "Configure Generation Defaults".

## Key conventions

- `common.ps1` is dot-sourced by build/package scripts only (not runtime scripts or configure/install scripts). Runtime scripts use `$PSScriptRoot` to resolve their own paths.
- `build\config-build.psd1` uses single-quoted PowerShell data-file syntax. All generated config files (`config.ini`, `models.ini`) are plain UTF-8 INI written without BOM, parsed by the same common-ini.ps1 helpers used at runtime.
- All build artifacts live under `.\build\` (gitignored): source clone, cmake binary dir, NSIS staging, `config-build.psd1`, generated `.nsi`. A single `rm -rf build\` or `Remove-Item -Recurse -Force build\` returns the repo to a clean state.
- The installer registers in `HKLM\Software\stable-diffusion.cpp` (InstallDir). Runtime user state lives under `%LOCALAPPDATA%\stable-diffusion.cpp\`: `config\config.ini` (generation defaults + server settings), `config\models.ini` (per-model INI sections, one per model .gguf/.safetensors file), `logs\` (sd-cli invocation logs). The uninstaller asks whether to delete the runtime tree.
- SD.cpp requires `--recursive` git clone because it depends on the ggml submodule. Build output binary paths: `build\cmake-build\bin\sd-cli.exe` and `build\cmake-build\sd-server.exe` (Windows CMake puts binaries directly in `bin\`, not a `<Config>\bin\` subfolder like llama.cpp does; both Release and Debug fallback locations are checked).
- Default compiler is MSVC (cl) — recommended by sd.cpp docs. LLVM/clang can be used if paths are manually configured.
