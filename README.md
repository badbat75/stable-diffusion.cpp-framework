# stable-diffusion.cpp-framework

> **Windows only** — all scripts are PowerShell (.ps1) and target Windows 10/11 exclusively.

PowerShell scripts to build and run [stable-diffusion.cpp](https://github.com/leejet/stable-diffusion.cpp) on Windows with multi-GPU backend support (CUDA, Vulkan, ROCm/HIP) and NSIS installer packaging. The web UI built into `sd-server` is used as the frontend — no separate UI is bundled. Mirrors the sibling `llama.cpp-framework` repo one-to-one (same script names, same INI layout, same install-time flow).

## Prerequisites

- Windows 10/11
- [Visual Studio](https://visualstudio.microsoft.com/) with C++ workload
- [Git](https://git-scm.com/)

Optional (installed automatically by scripts as needed):
- [CUDA Toolkit](https://developer.nvidia.com/cuda-toolkit)
- [Vulkan SDK](https://vulkan.lunarg.com/)
- [AMD HIP SDK (ROCm)](https://rocm.docs.amd.com/)
- [NSIS](https://nsis.sourceforge.io/) (for installer packaging, installed via winget if missing)

## Quick start

```powershell
# 1. Install / update the toolchain (elevates via UAC as needed).
#    Re-run any time to upgrade winget packages and pull stable-diffusion.cpp.
.\00-install-prerequisites.ps1

# 2. Auto-detect paths and generate config-build.psd1
.\01-configure.ps1

# Or override the stable-diffusion.cpp source clone location:
.\01-configure.ps1 -StableDiffusionCppDir "C:\path\to\my\stable-diffusion.cpp"

# 3. Build stable-diffusion.cpp
.\02-build-server.ps1

# 4. Build the sd-config GUI/CLI (Rust + Slint)
.\03-build-gui.ps1

# 5. Produce a Windows installer in dist\
.\04-package.ps1
```

## Layout

All build artifacts live under `build\` so a single `rm -rf build\` returns the repo to a clean state.

```
<repo>/
├── build/
│   ├── config-build.psd1            ← build-time config (generated by 01-configure.ps1)
│   ├── stable-diffusion-cpp.nsi     ← NSIS script (generated by 04-package.ps1, transient)
│   ├── stable-diffusion.cpp/        ← sd.cpp source clone (StableDiffusionCppDir, --recursive)
│   ├── cmake-build/                 ← cmake binary dir (out-of-source build)
│   └── staging/                     ← cmake staging area for NSIS
├── dist/                            ← final installer .exe
├── resources/                       ← scripts shipped inside the installer
└── *.ps1                            ← top-level build/run/package scripts
```

## Configuration

Settings are split between build-time and runtime so the same scripts work both in-tree and from a system install.

| File | Where | Purpose |
|------|-------|---------|
| `config-build.psd1` | `build\` (gitignored) | Build-time paths and GPU backend toggles. Generated by `01-configure.ps1`. |
| `server.ini` | `%LOCALAPPDATA%\stable-diffusion.cpp\config\` | Machine-wide sd-server runtime (port, host, threads, models dir). Single `[Server]` section. Written by the `sd-config` GUI/CLI. |
| `presets.ini` | `%LOCALAPPDATA%\stable-diffusion.cpp\config\` | Per-model presets: one `[<model-id>]` section each with model path, sub-model paths (vae, llm, t5xxl, clip_l, clip_g), memory knobs (offload, mmap, fa, max-vram), and default generation params (sampler, steps, cfg-scale, width, height). Translated into sd-server CLI args at launch time by `run-server.ps1`. Written by the `sd-config` GUI/CLI (rewriting one section at a time while preserving hand-edits in other sections). |

`config-build.psd1` keys:

| Section | Keys |
|---------|------|
| Paths | `StableDiffusionCppDir`, `HipPath`, `VsDevShell`, `CacheDir` |
| GPU backends (at most one true) | `SdCuda`, `SdVulkan`, `SdHipblas` |
| Build | `BuildType` |

Runtime configs are written on first launch by the `sd-config` GUI (the installer's Finish page offers to open it; `run-server.ps1` opens it lazily if any required file is missing). Re-runnable any time via the *Configure* Start Menu shortcut, or scripted via `sd-config server set ...` / `sd-config preset list` etc.

## Scripts

| Script | Description |
|--------|-------------|
| `00-install-prerequisites.ps1` | Idempotent toolchain bootstrapper. Installs missing winget packages (PowerShell 7+, NSIS) and upgrades present ones in a single UAC-elevated session; pulls stable-diffusion.cpp source (with submodules) when cloned; flags CUDA / Vulkan / HIP SDKs for manual install; reports version changes and recommends a rebuild only when sd.cpp source moved. |
| `01-configure.ps1` | Detects environment, verifies tools, auto-probes GPU toolchains, writes `config-build.psd1`. Accepts `-StableDiffusionCppDir`. |
| `02-build-server.ps1` | CMake configure (out-of-source into `build\cmake-build\`) + Ninja build. Auto-clones stable-diffusion.cpp `--recursive` into `build\stable-diffusion.cpp\` (ggml submodule). Throws if more than one GPU backend toggle is on. |
| `03-build-gui.ps1` | Builds the Rust/Slint `sd-config` configurator (`cargo build --release` in `sd-config\`). Errors with a clear message if `cargo` is not on PATH. |
| `04-package.ps1` | Stages from `build\cmake-build\bin\` into `build\staging\`, auto-invokes `03-build-gui.ps1` if `sd-config.exe` is missing, then runs NSIS to produce `dist\stable-diffusion-cpp-<version>-win64-setup.exe`. |
| `05-update-installed-scripts.ps1` | Dev convenience: hash-compares each file in `resources\` against the installed copy under `%ProgramFiles%\stable-diffusion.cpp\` and copies changed ones over. Self-elevates for the write. Binaries (`sd-server.exe`, `sd-config.exe`, ggml DLLs) are **not** touched — re-run `02-build-server.ps1` / `03-build-gui.ps1` + the installer for those. |
| `common.ps1` | Shared bootstrap: loads `$cfg` from `config-build.psd1`, prepends ROCm `bin\` to PATH, exposes `Enable-VsDevShell` as a function. VS Dev Shell activation is **opt-in** — only build/package scripts call it, runtime scripts don't pay the startup cost. |
| `sd-config\` | Rust crate producing `sd-config.exe` — a single dual-mode binary. No args → Slint GUI (Server / Models / MCP tabs). With subcommands → CLI: `sd-config server show\|set`, `sd-config preset list\|show\|delete`, `sd-config mcp status\|install\|uninstall <client>`. Writes the same INI/JSON files documented in *Configuration*. |
| `resources\run-server.ps1` | Runtime entry point shipped with the installer. Reads `server.ini` + `presets.ini`, picks one preset (auto if only one, interactive picker otherwise; `-Preset <id>` skips the prompt), translates it into sd-server CLI args, and launches sd-server. The user interacts with sd-server's built-in web UI at `http://<host>:<port>/`. Launches `sd-config.exe` (blocking) if `server.ini` / `presets.ini` are missing. Accepts `-ServerExe` to override the sd-server binary location. |
| `resources\mcp-server.ps1` | Model Context Protocol bridge (stdio, JSON-RPC 2.0) that lets MCP-aware agents (Claude Code, etc.) drive the running sd-server. Exposes seven tools: `generate_image`, `get_model_info`, `encode_file_base64`, `server_status`, `list_presets`, `switch_preset`, `stop_server`. See *MCP integration* below. |
| `resources\common-functions.ps1` | Read-side helpers dot-sourced by `run-server.ps1` and `mcp-server.ps1`: `Read-ServerIni`, `Get-Presets`, `Read-SdServerState`, plus `ConvertTo-IntOrNull` / `FloatOrNull` / `BoolOrNull`. INI writes happen in Rust (`sd-config\src\ini.rs`). |

## Packaging

`04-package.ps1` produces a Windows installer at `dist\stable-diffusion-cpp-<version>-win64-setup.exe`. The installer:

- Installs stable-diffusion.cpp binaries (sd-server + sd-config) to `C:\Program Files\stable-diffusion.cpp\`.
- Optionally adds `bin\` to the system PATH.
- Creates Start Menu shortcuts (`stable-diffusion.cpp`, *Configure*, *Uninstall*); the launcher targets `pwsh.exe` running `run-server.ps1`, *Configure* points at `sd-config.exe` directly.
- Offers a Finish-page checkbox "Launch the configuration tool now" (default unchecked); when ticked, spawns `sd-config.exe` via `explorer.exe` so it runs un-elevated and writes to the calling user's `%LOCALAPPDATA%`. All runtime configuration happens post-install in the GUI — there is no install-time config page.
- Supports upgrades (silently uninstalls the previous version first).
- Includes a full uninstaller in Add/Remove Programs. By default it preserves `%LOCALAPPDATA%\stable-diffusion.cpp\` (configs, logs) across uninstalls; the user can opt in to a full wipe.

NSIS is installed automatically via winget if not already present.

## MCP integration

`resources\mcp-server.ps1` is a Model Context Protocol bridge (stdio JSON-RPC) that lets MCP-aware agents call into a running `sd-server`. It's wired up two ways:

- **In-repo development** — `.mcp.json` at the repo root is auto-detected by Claude Code; it uses a relative path so it works on any clone location.
- **Installed** — open the *Configure* shortcut (or run `sd-config.exe`), switch to the MCP tab, and click *Install* next to the target client (Claude Code / Claude Desktop / OpenCode). The GUI surgically inserts a `stable-diffusion-cpp` entry into the client's own config file (`~/.claude.json`, `%APPDATA%\Claude\claude_desktop_config.json`, or `~/.config/opencode/opencode.json`) without touching unrelated entries. Equivalent CLI: `sd-config mcp install claude-code|claude-desktop|opencode`.

Either way, once `sd-server` is up the agent can call `generate_image`, `get_model_info`, `list_presets`, `switch_preset`, `server_status`, `stop_server`, and `encode_file_base64`. The bridge reads sd-server's pid / host / port from `%LOCALAPPDATA%\stable-diffusion.cpp\run\sd-server.state` (written by `run-server.ps1` while sd-server is alive), so a `switch_preset` mid-session is observed without restarting the bridge.

## GPU backend notes

Only one GPU backend may be active per build (CUDA, Vulkan, or HIP). `01-configure.ps1` auto-probes for the installed toolchains and picks one with priority **CUDA > Vulkan > HIP**, writing the matching toggle to `config-build.psd1`. Edit the `.psd1` to force a different backend.

### CUDA
Requires NVIDIA GPU with a recent CUDA Toolkit installed; `nvcc` must be on PATH after VS Dev Shell activation.

### Vulkan
Works on any GPU with up-to-date Vulkan drivers. Needs the Vulkan SDK (provides `glslc.exe`); auto-detected via `VULKAN_SDK` env var or `%ProgramFiles%\VulkanSDK\*\Bin\glslc.exe`.

### ROCm / HIP
Requires AMD GPU with ROCm drivers. On Windows ROCm support is limited to specific AMD GPUs (typically RX 6000-series and newer). `02-build-server.ps1` switches to the HIP-bundled clang when `HIP_PATH\bin\clang.exe` exists.
