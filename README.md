# stable-diffusion.cpp-framework

> **Windows only** — all scripts are PowerShell (.ps1) and target Windows 10/11 exclusively.

PowerShell scripts to build and run [stable-diffusion.cpp](https://github.com/leejet/stable-diffusion.cpp) on Windows with multi-GPU backend support (CUDA, Vulkan, ROCm/HIP) and NSIS installer packaging. Primary workflow uses `sd-cli` for image generation; `sd-server` provides an optional API endpoint via a local HTTP server.

## Prerequisites

- Windows 10/11
- [Visual Studio](https://visualstudio.microsoft.com/) with C++ workload (MSVC recommended)
- [Git](https://git-scm.com/)

Optional (installed automatically by scripts as needed):

- [CUDA Toolkit](https://developer.nvidia.com/cuda-toolkit)
- [Vulkan SDK](https://vulkan.lunarg.com/)
- [AMD HIP SDK (ROCm)](https://rocm.docs.amd.com/)
- [NSIS](https://nsis.sourceforge.io/) (for installer packaging, installed via winget if missing)

## Quick start

```powershell
# 1. Install / update the toolchain (elevates via UAC as needed).
#    Re-run any time to upgrade winget packages and pull sd.cpp.
.\00-install-prerequisites.ps1

# 2. Auto-detect paths and generate config-build.psd1
.\01-configure.ps1

# Or override the sd.cpp source clone location:
.\01-configure.ps1 -SdCppDir "C:\path\to\my\stable-diffusion.cpp"

# 3. Build stable-diffusion.cpp
.\02-build.ps1

# 4. Produce a Windows installer in dist\
.\03-package.ps1
```

## Layout

All build artifacts live under `build\` so a single `rm -rf build\` returns the repo to a clean state.

```
<repo>/
├── build/
│   ├── cmake-build/          ← cmake binary dir (out-of-source build)
│   ├── config-build.psd1     ← build-time config (generated by 01-configure.ps1)
│   ├── staging/              ← cmake --install + runtime scripts staging for NSIS
│   └── stable-diffusion.cpp/ ← sd.cpp source clone (--recursive, includes ggml submodule)
├── dist/                     ← final installer .exe
├── resources/                ← scripts shipped inside the installer / Start Menu shortcuts
│   ├── common-ini.ps1       ← INI parser/writer helpers (Read-ConfigIni, Set-ConfigField, etc.)
│   ├── config-generate.ps1  ← generation defaults writer (config.ini)
│   ├── config-model.ps1     ← per-model settings writer (models.ini)
│   └── run-generate.ps1     ← main image generation entry point (scans models, runs sd-cli)
├── AGENTS.md                 ← AI agent project guide
├── *.ps1                     ← top-level build/run/package scripts
└── stable-diffusion-cpp.nsi.template   ← NSIS installer template
```

## Configuration

Settings are split between **build-time** and **runtime**:

### Build time (`build\config-build.psd1`)

Generated by `01-configure.ps1`. Holds:

| Field              | Description                                |
| ------------------ | ------------------------------------------ |
| `VsDevShell`       | Path to `InitializeVsBuildEnvironment.ps1` |
| `Cmake`, `Ninja`, `Git` | Detected tool paths                        |
| `SdCuda`, `SdVulkan`, `SdHipblas` | GPU backend feature flags (`true`/`false`)  |
| `CppDir`           | sd.cpp source clone location               |

### Runtime (`%LOCALAPPDATA%\stable-diffusion.cpp\config\`)

Written by the script starters on first launch (or by the NSIS installer config page):

| File             | Purpose                                        |
| ---------------- | -----------------------------------------------  |
| `config.ini`     | Generation defaults, server settings, output dir |
| `models.ini`     | Per-model INI sections — one per .gguf/.safetensors file (prompt, dimensions, steps, sampling params, seed) |

The config page at install time asks for:

- **Models folder** — directory where `.gguf` / `.safetensors` weight files live
- **SD Server port** — HTTP port for `sd-server`, or disable it entirely
- **Output directory** — where generated images are saved (default: `%USERPROFILE%\Pictures\sd-cpp-output`)
- **Number of threads** — defaults to half of available CPU cores

Model-dependent parameters (prompt, width, height, steps, CFG scale, sampling method, seed) are configured per-model via the "Configure Model" Start Menu shortcut. They are NOT prompted at install time because sd.cpp has no model routing — each image run picks one model from disk.

## Getting started with generated images

### Install-time (via installer)

Running `03-package.ps1` produces an NSIS installer. Double-click the `.exe` to install; it will ask for your models folder, server settings, and thread count on a config page. After installation:

1. Place `.gguf` or `.safetensors` files in the configured models folder.
2. Open **Start Menu → stable-diffusion.cpp → Generate Image**.
3. Select your model → enter (or accept defaults for) prompt, settings.
4. The generated PNG is saved to `OutputDir\YYYYMMDD-HHMMSS\modelname_timestamp.png` and auto-opened.

### Manual (in-tree development)

```powershell
# Generate your first image:
$ cd resources
$ .\run-generate.ps1

# Or skip the model picker (uses DefaultModelName from config.ini):
$ .\run-generate.ps1 -Auto

# Edit per-model settings:
$ .\config-model.ps1

# Configure generation defaults (server port, output dir, etc.):
$ .\config-generate.ps1
$ .\config-generate.ps1 -NonInteractive  # headless mode
```

## SD.cpp CMake options

| Option                    | Description                         |
| ------------------------- | -----------------------------------  |
| `-DSDBUILD_EXAMPLES`     | Build sd-cli and sd-server          |
| `-DSD_CUDA`              | Enable CUDA backend                  |
| `-DSD_VULKAN`            | Enable Vulkan backend                |
| `-DSD_HIPBLAS`           | Enable AMD ROCm/HIP backend          |

The build scripts use the GPU flags set in `config-build.psd1`. No OpenSSL dependency — sd.cpp does not use it.

## Uninstalling

The installer provides a Start Menu shortcut to uninstall. The wizard asks (default: **No**) whether to delete the runtime tree (`%LOCALAPPDATA%\stable-diffusion.cpp\`), so your models and generated images are preserved across reinstall or upgrade. If you built in-tree, just run:

```powershell
Remove-Item -Recurse -Force build\
```

## GPU backend notes

The install script probes for SDKs but does not auto-install them — manual installation is required for CUDA Toolkit (NVIDIA), Vulkan SDK (any), or AMD HIP SDK / ROCm (AMD). The configure/build scripts set the matching CMake flag (`SD_CUDA`, `SD_VULKAN`, `SD_HIPBLAS`) when an SDK is detected. Build with whichever backend suits your hardware; only one can be active at a time per compilation.

### CUDA
Requires NVIDIA GPU ≥ Pascal architecture (compute capability 5.0+). Install [CUDA Toolkit](https://developer.nvidia.com/cuda-toolkit) and ensure `nvcc` is on PATH. Set `-DCMAKE_CUDA_ARCHITECTURES=60;70;80` if targeting specific generations.

### Vulkan
Works on any GPU with updated Vulkan drivers. The Vulkan SDK install provides `glslc.exe`; configure the path manually in `config-build.psd1` if not auto-detected.

### ROCm / HIP
Requires AMD GPU with ROCm drivers. The install script probes for HIP and sets `HIP_PATH`. Note: on Windows ROCm support through HIP is limited to specific AMD GPUs (typically RX 6000-series and newer). Set `-DAMDGPU_TARGETS=gfx1030;gfx1100` to target specific chip families.

## Troubleshooting

| Problem                                  | Solution                                         |
| ----------------------------------------- | --------------------------------------------------- |
| `config-build.psd1 not found`            | Run `.\01-configure.ps1` first                       |
| `VsDevShell not configured / not found`  | Install Visual Studio with the "Desktop development with C++" workload and re-run configure |
| CUDA build fails (`nvcc not found`)       | Install CUDA Toolkit and ensure it's on PATH, then rerun `-01-configure.ps1` (it probes for toolchain paths) |
| sd-cli exits with an error                | Check `%LOCALAPPDATA%\stable-diffusion.cpp\logs\` for sd-cli stdout/stderr output |
| No models found                           | Place `.gguf` or `.safetensors` weight files in the configured ModelsFolder from `config.ini` or set via "Configure Generation Defaults" shortcut |
